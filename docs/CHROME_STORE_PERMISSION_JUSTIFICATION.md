# Chrome Web Store permission justification

**Status: PARTIAL (local manifest reviewed; public review pending)**

The current local manifest is generated by WXT from
`apps/extension/wxt.config.ts`. This document covers the local implementation;
Google OAuth client configuration, restricted-scope review, and store review
remain manual gates.

## Single purpose

The extension has one purpose: help a single Gmail user use the Subzero Mail
inbox workflow to focus, read, search, and manage mail. It injects only into
`https://mail.google.com/*` through an isolated-world content script and does
not inspect unrelated websites or request browsing history.

## Exact Google OAuth scopes from the current repository

The web client constructs its authorization request with this exact set:

```text
https://www.googleapis.com/auth/gmail.modify
openid
email
profile
```

`gmail.modify` is the Gmail read/modify scope currently used by the web client.
It covers the implemented Gmail-first workflow, including reading mail and
mailbox mutations such as labels/read state/archive, plus draft/send routes.
It is a restricted Google scope. This list is source evidence for the web app,
not proof that a future extension has requested or been approved for it.

Source: [`apps/web/app/api/auth/google/oauth.ts`](../apps/web/app/api/auth/google/oauth.ts).

Do not conflate these with Chrome permission names:

- `identity` is a Chrome extension permission candidate.
- `openid`, `email`, and `profile` are Google identity scopes.
- `gmail.modify` is a Google Gmail OAuth scope.

If the extension delegates OAuth to the web app, document the handoff and the
token boundary explicitly. If it owns OAuth, use a dedicated extension client
and prove the final redirect/origin configuration manually.

## Data-use disclosure draft

Use this only after implementation review:

> Subzero Mail uses Gmail access to show and manage the connected user's Gmail
> account. The service may process the current thread or a bounded evidence set
> for user-requested triage, summaries, inbox questions, or drafts. When an AI
> feature is used, the selected content is sent to the provider chosen and paid
> for by the user. OAuth credentials and provider keys must remain outside
> browser storage where the current web implementation stores them: encrypted
> on the server. Subzero Mail does not use email content, OAuth tokens, provider
> keys, or AI prompts for product analytics by default.

This disclosure covers the local extension boundary. Recheck it if the
extension adds direct page access, a new relay, provider settings, or
background processing beyond metadata sync.
