# Client parity: web versus Chrome extension

**Status: PARTIAL**

Web evidence remains independent from extension evidence. `PASS (local/demo)`
means the extension was built and exercised with fixtures or a local Chromium
surface; it does not prove live Gmail DOM behavior, clean-profile OAuth,
Google verification, provider, notification, or store behavior. `PASS (live
code)` is intentionally not used as a release gate: code presence is not live
acceptance.

## Release gaps

The extension is a real MV3 client with local/demo P0 and high-value P1
surfaces: Gmail API search/thread/star/draft/send, a Gmail-only content script
with Shadow DOM contextual controls, the Side Panel, sanitized HTML rendering,
grounded summaries and intent drafts, bounded Ask Inbox, Open Loops/reminders
and notifications, session-only BYOK, and logout/cache clearing. Public/live
parity still requires clean-profile Gmail DOM and OAuth verification, Side Panel
and reminder delivery checks, live provider/network verification where
applicable, revoke/deletion evidence, consent and Google restricted-scope review
for the configured client, final permission/data-use review, release signing,
a verified public privacy/support URL, and Chrome Web Store review. Local
screenshots and draft text are not store or live evidence.
